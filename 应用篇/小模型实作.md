# 应用篇一 · 小模型实作：从零训一个自己的 GPT

> 位置：本仓四卷是"读论文"，这一篇是"动手"。读完第三卷的 Transformer 和大模型，再来这里把同一个架构亲手写出来、训出来。顺序反过来也行——先动手，再回头读论文，很多句子会突然有了画面。

## 先把概念说清

### 小语言模型（SLM）是什么

语言模型做的事只有一件：给它一段文字，它预测下一个词（或下一个字符）最可能是什么。所谓"大"和"小"，指的只是参数量——模型内部那些可调节的数字有多少。

- 大模型：几百亿到上万亿参数，要一屋子显卡才训得动、跑得起，比如 GPT-3 是 1750 亿参数（见 [GPT-3 全文精译](../全文精译/07-GPT3-2020.md)）。
- 小模型：几百万到几十亿参数。一台普通电脑、甚至手机就能跑；几千万参数的模型，一块消费级显卡一下午就能从零训完。

要注意：小模型不是"另一种技术"。它和大模型用的是同一个架构（Transformer）、同一套训练方法、同一种生成方式。差别只在规模。这正是关键——**架构学会了，大小只是数字**。第三卷的 [Scaling Laws](../第三卷-Transformer与大模型.md) 讲的就是这件事：模型变大、数据变多、算力变多，能力按可预测的曲线往上走，中间没有换过魔法。

### 为什么先学小模型，学得反而快

1. **反馈快**。训大模型等一次结果要几天；训字符级小模型，改一行代码几分钟后就看到效果。学东西靠的就是"改一下、看一眼"的循环次数，循环越快，学得越快。
2. **代码能看全**。一个小 GPT 的全部代码三四百行，一页页翻得完。大模型的工程代码几十万行，新手进去就迷路。
3. **犯错便宜**。学习率设错、数据喂错，小模型几分钟后 loss 不降，你立刻知道错了。在大模型上犯同样的错，代价是几天电费。
4. **该有的零件一个不少**。token、embedding、attention、残差连接、归一化——大模型有的，小模型全有，只是尺寸小。把小模型拆透，大模型的论文就剩读数字了。

## 动手路线

全程主线是 Andrej Karpathy 的公开教学：视频系列 *Neural Networks: Zero to Hero*（YouTube 频道 @AndrejKarpathy）和代码仓 [karpathy/nanoGPT](https://github.com/karpathy/nanoGPT)。他的代码不长，讲解是照着论文一行行写的，正好和本仓的精译对照着看。

### 第 0 步（可选热身）：先看梯度是怎么回事

- **目标**：对"训练 = 算梯度、调参数"有手感，不被后面的自动求导吓住。
- **做什么**：看 Zero to Hero 第一讲 micrograd，自己跟着写一个几十行的自动求导小引擎。它讲的正是 [反向传播](../全文精译/01-反向传播-1986.md) 那篇 1986 年的论文，只是用代码讲。
- **时长量级**：一个晚上。
- **过关标准**：能用自己的话说清三件事——loss 是什么、梯度指向哪、学习率大了小了分别会怎样。说不清就先停在这里，别往下赶。

### 第 1 步：从空文件写一个字符级 GPT

- **目标**：把 Transformer 的每个零件亲手写一遍，知道它们在代码里长什么样。
- **做什么**：跟视频 *Let's build GPT: from scratch, in code, spelled out*（2023 年 1 月，约两小时）从空文件开始，先写一个只看前一个字符猜下一个字符的笨模型，再一步步加上自注意力、多头、堆叠层，最后在莎士比亚文本上训一个字符级模型。数据是 tiny Shakespeare：一共一百多万个字符，词表只有 65 个字符——每个字符就是一个 token，简单到没有藏身之处。
- **边写边对照**：每写到一个部件，翻开 [Attention Is All You Need 全文精译](../全文精译/05-Attention-Is-All-You-Need-2017.md) 找它在论文里的原话：
  - **token 与 embedding**：字符先变成编号，再查一张表变成一串数字（向量）。这张表是学出来的，不是人编的。
  - **位置编码**：模型本身分不清先后，所以要把"第几个位置"也编码进向量里。
  - **自注意力（self-attention）**：每个位置回头看前面所有位置，自己决定该重点看谁。论文里那句 "Attention is all you need" 落到代码里就是几十行矩阵乘法。它的前身是 2015 年的 [Bahdanau 注意力](../全文精译/03-Bahdanau注意力-2015.md)，先用在翻译上。
  - **多头（multi-head）**：同一件事并行看好几遍，每遍关注点不同，最后拼起来。
  - **残差连接与 LayerNorm**：让深层网络训得动的基本功，原理在 [ResNet 精译](../全文精译/04-ResNet-2015.md) 里讲过同一件事的图像版。
- **时长量级**：视频两小时，跟着敲加停下来想，预留两个晚上。
- **过关标准**：合上视频，能自己从空文件把这个小 GPT 再写出来（写不出就再跟一遍，不丢人）；并且能指着代码说出：哪几行是 embedding、哪几行是 attention、训练时喂进去的输入和标签差了几位。

### 第 2 步：用 nanoGPT 正经训一个

- **目标**：从"教学玩具"过渡到"真实训练脚本"，看懂一个训练项目长什么样。
- **做什么**：打开 [karpathy/nanoGPT](https://github.com/karpathy/nanoGPT)。整个仓核心就两个文件：`model.py`（约 300 行，模型定义）和 `train.py`（约 300 行，训练循环）。先在 tiny Shakespeare 上把字符级配置跑通，看 loss 一路往下掉，再抽样看看生成的文本从胡言乱语慢慢变成像模像样的莎士比亚腔。然后试着改三个参数玩一玩：层数、embedding 维度、学习率——每次只改一个，记下 loss 的变化。
- **时长量级**：跑通半天；玩参数再半天。
- **过关标准**：能说清 train.py 里一个训练步（step）发生了什么：取一批数据 → 前向算 loss → 反向算梯度 → 更新参数；能解释为什么 loss 曲线是抖着往下走的，而不是一条直线。

### 第 3 步：换上真正的 tokenizer，摸到 GPT-2 的门

- **目标**：理解真实模型为什么不用字符级切分，以及"放大规模"具体放大了什么。
- **做什么**：看 Zero to Hero 的 *Let's build the GPT Tokenizer* 一讲，理解 BPE（字节对编码）：把常见字串合并成一个 token，GPT-2 的词表是 50257 个 token。然后粗读 nanoGPT 加载 GPT-2 权重的那部分代码——你会发现 GPT-2（第三卷有导读）的架构和你第 1 步手写的几乎一模一样，只是层数、维度、词表都放大了。想再往深走的，可以看他 2024 年的 *Let's reproduce GPT-2 (124M)* 长视频和配套仓 karpathy/build-nanogpt：在一张到八张显卡上把 GPT-2 从零复现出来。
- **时长量级**：tokenizer 一讲一个晚上；复现 GPT-2 是选修，有显卡再说，不必卡在这。
- **过关标准**：能回答：为什么英文文本里一个 token 平均约等于 0.75 个单词？为什么词表大小会同时影响 embedding 表和最后一层输出的尺寸？

### 第 4 步：微调——让模型学会按你的要求说话

从零训练教的是"接着往下写"，微调（fine-tuning）教的是"听指令、按格式答"。两件事的直觉分开记：

- **SFT（监督微调）是什么**：准备一批"问题 → 理想回答"的例子，继续训模型，让它模仿这些回答的口气和格式。数据不在多在对口：一千条认真写的例子，胜过十万条凑数的。[InstructGPT 精译](../全文精译/08-InstructGPT-2022.md) 讲的就是这条路再往后一步——SFT 之后再用人类反馈做强化学习（RLHF），ChatGPT 就是这么来的。本篇只做到 SFT 理解加一次小实作，RLHF 知道它在哪一步、解决什么问题即可。
- **LoRA 是什么**：全量微调要动模型全部参数，贵且每个任务存一份完整权重。LoRA 的办法是把原模型冻住不动，只在旁边挂一对小矩阵（低秩矩阵）来训练，训完的参数量常常不到原模型的百分之一，效果却接近全量微调。打个比方：不重写整本书，只在页边贴一层批注纸。原论文在第三卷（[LoRA, 2021](../第三卷-Transformer与大模型.md)），公式不难，建议对着导读读一遍。
- **做什么**：用 Hugging Face 的 [PEFT 库](https://github.com/huggingface/peft) 给一个开源小模型（比如 1B 上下的指令模型）挂上 LoRA，喂几百条你自己领域的问答例子（自己的笔记、某个设备的故障问答都行），训完对比微调前后的回答。
- **时长量级**：环境和数据准备大半天，训练本身一两个小时起。
- **过关标准**：能说清三件事——SFT 的训练数据长什么样；LoRA 训的到底是哪部分参数、为什么省显存；微调能改变模型的"说话方式和领域知识倾向"，但灌不进大量新事实知识（那是 RAG 的活，见 [Agent 实作篇](Agent实作.md)）。

### 第 5 步：量化与导出——把模型装进自己的电脑

- **目标**：理解模型文件为什么能从十几 GB 变成几 GB，并且亲手把一个模型在本机跑起来，为后面的本地部署篇打底。
- **先讲清量化是什么**：模型参数原本每个用 16 位浮点数存（FP16）。量化就是把它们压缩成 8 位、4 位整数来存，体积和内存占用直接除以二、除以四，速度还更快；代价是精度略降，4 位量化在日常对话里多数人感觉不出差别。这就像把无损音乐压成高码率 MP3：文件小了一大截，耳朵很难分辨。
- **做什么**：用 [llama.cpp](https://github.com/ggml-org/llama.cpp)（本地跑模型的主力工具，现在由 ggml-org 维护）把一个 Hugging Face 上的开源模型转成 GGUF 格式（它自家的单文件格式），再用它自带的 `llama-quantize` 压成 Q4_K_M（社区最常用的 4 位档），最后用 `llama-cli` 在自己电脑上和它聊两句。想省事的可以直接用 [Ollama](https://github.com/ollama/ollama)：一条命令拉模型、跑模型，还能导入你自己转好的 GGUF 文件。
- **时长量级**：半天。
- **过关标准**：手边有一个自己转出来、能在本机离线跑的 GGUF 文件；能说清 Q4、Q8、FP16 三个版本体积差多少、回答质量差在哪、各自适合什么机器。

## 走完这条线的自检

能不用查资料回答下面这些问题，这一篇就算过关：

1. 语言模型训练时到底在优化什么？（提示：和"背课文"有什么区别）
2. attention 里的 Q、K、V 分别在干什么，为什么要多头？
3. 字符级 token 和 BPE token 各有什么代价？
4. 一个 7B 模型，FP16 存要多大空间，Q4 量化后多大？
5. 想让模型学会用你公司的口气回邮件，你选 SFT、LoRA 还是改提示词？为什么？
6. 别人说"这个模型有 700 亿参数"，你脑子里能立刻换算出它大概要多少显存才跑得起来吗？
