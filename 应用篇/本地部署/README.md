# 本地私有化部署：把大模型装进自己的机器

前面几卷讲的是论文——模型为什么长这样、怎么训练出来的。这一篇讲动手：把一个开源模型下载到自己的电脑或服务器上跑起来，数据不出门，断网也能用。

## 为什么要在本地跑

- **数据不出门。** 聊天记录、公司文档、代码，都只在你自己的硬盘和内存里转，不经过任何云厂商。处理敏感材料时，这一点比什么都重要。
- **不按量付费。** 云端 API 是按 token 收费的，本地跑的成本只有电费。用得多的时候差距很明显。
- **断网可用，不受限速。** 模型下好之后，飞机上、内网里都能用，也没有谁会在半夜给你发一封"额度已用完"的邮件。
- **想换就换。** 今天试这个模型，明天试那个，不需要跟任何平台申请。

代价也要说清楚：硬件是你自己的，模型能有多聪明，先被你的显存大小卡住；出了问题得自己查。云端那种"打开网页就能用 GPT 级别模型"的体验，本地短期内给不了。但对学习、开发和处理私有数据来说，本地完全够用，而且这是理解模型最快的方式——它就实实在在跑在你的机器上。

## 三条路线，先选对再动手

本地跑模型，工具很多，但主流就三条路线，定位完全不同：

| | Ollama | llama.cpp | vLLM |
|---|---|---|---|
| 一句话 | 装好就能聊的成品 | 什么硬件都能跑的手动挡 | 为多人并发而生的服务器引擎 |
| 上手难度 | 一条命令安装，一条命令运行 | 要自己下模型文件、敲参数 | 要懂一点服务器和 Python 环境 |
| 适合的硬件 | 笔记本、台式机、Mac 都行 | 从树莓派级小设备到工作站，包括纯 CPU | 带 NVIDIA 显卡的 Linux 服务器 |
| 模型格式 | 自家模型库，一键拉取 | GGUF 单文件 | Hugging Face 原始权重 |
| 并发能力 | 个人使用足够 | 个人使用足够 | 强项：几十上百个请求同时处理 |
| 接口 | 自带 REST API，兼容 OpenAI 格式 | 自带 HTTP 服务，兼容 OpenAI 格式 | 原生 OpenAI 兼容 API |

选择建议很简单：

- **只是想在自己的笔记本上玩一玩、学一学** → Ollama，十分钟就能聊上。
- **机器比较老、没有像样的显卡，或者想搞明白每个参数在干什么** → llama.cpp，它对硬件最宽容，调得也最细。
- **要给团队、给产品提供 API 服务，很多人会同时用** → vLLM。个人自用没必要上它，启动慢、配置多，单人聊天的体验并不比 Ollama 好。

## 显存要多大：一个能自己算的方法

新手最常问的问题是"我的显卡能跑多大的模型"。算法不难，分两块：

**第一块是模型权重本身。** 权重占多少空间，取决于参数量和每个参数用多少位来存（这就是"量化"，在 llama.cpp 分册里细讲）。速算系数如下——参数量以"十亿"（B）为单位：

| 存放方式 | 每个参数约占 | 8B 模型权重大约 |
|---|---|---|
| FP16 / BF16（原始精度） | 2 字节 | 约 16 GB |
| Q8_0 量化 | 约 1.05 字节 | 约 8.5 GB |
| Q6_K 量化 | 约 0.82 字节 | 约 6.5 GB |
| Q5_K_M 量化 | 约 0.71 字节 | 约 5.5 GB |
| Q4_K_M 量化（最常用） | 约 0.6 字节 | 约 4.7 GB |
| Q3_K_M 量化 | 约 0.49 字节 | 约 3.5 GB |

举例：一张 12 GB 显存的显卡，跑 8B 的 Q4_K_M（约 4.7 GB）绰绰有余；跑 14B 的 Q4_K_M（约 8.5 GB）也行；想跑 32B，就得用 Q4 量化加一部分层卸载到内存（llama.cpp 能做），或者干脆放弃。

**第二块是 KV 缓存和运行开销。** 模型每读一个字，都要把上下文记下来备查，聊得越长、同时聊的人越多，这块占得越多。所以别把显存算得严丝合缝：权重的数字之外，再预留两成左右的余量，长对话场景留得更多。

**没有独立显卡的情况：**

- 苹果芯片的 Mac 用的是统一内存，内存就是显存池。16 GB 内存的 Mac 跑 8B 的 Q4 量化没问题，但系统和别的软件也要吃内存，别指望把 16 GB 全给模型。
- 纯 CPU 也能跑（llama.cpp 和 Ollama 都支持），小模型可以，大模型会慢到失去耐心。把它当作兜底方案。

把三件事套在一起算：`能用的显存 ≥ 权重大小 × 1.2`，够就跑，不够就降一档量化或换小一号的模型。

## 模型从哪儿下

只从两个地方下，别用来路不明的文件：

1. **Ollama 模型库**（ollama.com/library）。Ollama 用户的主渠道，模型已经按它的格式打包好，`ollama pull 模型名` 一条命令拉下来。Meta、Google、阿里等厂商的热门开源模型基本都有。
2. **Hugging Face**（huggingface.co）。开源模型的集散地，llama.cpp 用的 GGUF 文件和 vLLM 用的原始权重都在这里。下载时认准发布者：模型原厂的官方账号，或者 ggml-org、bartowski、unsloth 这类长期维护 GGUF 转换的知名账号。

两个提醒：

- 有些模型（最典型的是 Meta 的 Llama 系列）是"受限发布"：要在 Hugging Face 的模型页面先点同意它的许可协议，再登录账号（命令行里配好 token），才下得下来。这不是收费，是许可流程。
- 模型文件动辄几个 GB 到几十个 GB，下载前先看清文件大小和自己的硬盘余量。

## 本地跑和论文是什么关系

跑通这一篇，你对前面论文里的几个概念会有体感：参数量不再是论文表格里的数字，而是你硬盘上实实在在的几个 GB；上下文长度就是 KV 缓存吃掉的显存；量化就是拿一点点回答质量换能装得下。先跑起来，再回头看论文，很多地方会突然通了。
